I walked the current snapshot builder, character restore handler, concrete-tail restore, cleanup passes, the cChr/uCharacter Ghidra structures, constructors, property builders, and gameplay readers.
The mod captures the complete DTI-sized character body, but does not reliably restore the complete gameplay state. The generic pointer-looking-word scan in rollback_restore.cpp:1087 preserves arbitrary live 8-byte words, and the explicit ranges only repair selected pieces afterward.
The exact missing or incomplete areas are below.

1. The Fundamental Restore Bug
In rollback_restore.cpp:1084-1133, the character restore scans the body and preserves any 8-byte word where either the saved or live value passes IsLikelyPointer().
if (IsLikelyPointer(liveValue) || IsLikelyPointer(savedValue))
    livePointers.push_back(...);
This runs over the entire character body, including:
- cChr scalar state
- animation state
- hit/combat counters
- throw state
- command state
- packed flags
- vectors and float pairs
- MtArray headers
Then the explicit ranges attempt to repair some of the damage.
This means the answer is not “one missing range.” The current implementation has an unsafe default policy: gameplay scalars are preserved whenever their bytes happen to resemble addresses.

6. What I Would Change
Do not add another handful of ranges to the existing heuristic. The correct repair is:
1. Restore all inline cChr bytes as scalar state by default.
2. Preserve only known lifecycle/resource pointers.
3. Explicitly remap:
   - +0x6718
   - +0x6720
   - +0x6728
   - +0x6730
4. Explicitly preserve embedded object vtables and MtArray allocation headers.
5. Explicitly restore the payload of:
   - cAtkCtrl
   - both command matchers
   - cChrJointHold
   - messages
   - pause state
   - shot/relation state
6. Reapply relationship state after RestoreShotAndEffectRecipes() and after UI/native post-sync repairs.
7. Restore throw animation selectors and relation flags after those same repair passes.
The minimal immediate fix for the current throw investigation is to restore the full relation/shot state block and all four relationship pointers coherently:
+0x6710..+0x683F
with pointer slots remapped individually, rather than preserving them through IsLikelyPointer().
But the complete fix is to remove the body-wide pointer heuristic for cChr. That heuristic is the reason these gaps keep reappearing in different forms.
